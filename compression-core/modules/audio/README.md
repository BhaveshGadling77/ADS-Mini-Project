# Audio Compression and Decompression Using Huffman Coding

## Overview

This module is part of the **Advanced Data Structures Mini Project**. It implements lossless Huffman compression and decompression for audio data using C++.

The web GUI accepts MP3 files and invokes these binaries through the API. Its `.huf` archive contains Huffman-coded PCM; restored MP3 output is re-encoded and may differ from the original MP3.

MP3 input is decoded into raw PCM using FFmpeg before Huffman coding. Raw `.pcm` input is Huffman-coded directly and is assumed to be signed 16-bit little-endian, 44.1 kHz, stereo. Both paths create a custom binary `.huf` file.

During decompression, the PCM bytes are reconstructed and encoded to MP3 using FFmpeg. The PCM Huffman round trip is byte-preserving; MP3 output is lossy.

## Features

- MP3-to-PCM conversion using FFmpeg.
- Custom Huffman compression implemented in C++.
- Frequency-based Huffman tree construction using a min-priority queue.
- Binary encoding and decoding of PCM data.
- Custom `.huf` file format containing a header, original file size, frequency table, and encoded bitstream.
- Automatic reconstruction of PCM data.
- PCM integrity verification using SHA-256 hashes.
- MP3 re-encoding and file-size comparison.

## Technology Stack

## How It Works

### 1. Compression

1. The user supplies an MP3 file.
2. FFmpeg decodes the MP3 into raw PCM using signed 16-bit samples, a 44.1 kHz sample rate, and two audio channels.
3. The program counts the frequency of each possible byte value (0–255).
4. A Huffman tree is built using a min-priority queue.
5. Binary codes are generated by traversing the tree.
6. PCM bytes are encoded into a bitstream.
7. The frequency table, original byte count, and encoded bitstream are written to a `.huf` file.
8. Compression statistics are displayed.

### 2. Decompression

1. The program reads the `.huf` file.
2. It validates the file header and reads the original byte count and frequency table.
3. It reconstructs the Huffman tree.
4. The encoded bitstream is decoded by traversing the tree.
5. The original PCM data is written to a temporary file.
6. FFmpeg encodes the reconstructed PCM into a new MP3 file.

### 3. Verification

The original PCM and reconstructed PCM should be byte-for-byte identical. Their SHA-256 hashes can be compared to verify the correctness of Huffman decompression.

The original and re-encoded MP3 files may differ in size and encoded content because MP3 encoding is lossy.

## Installation and Requirements

### Install a C++ compiler

Install GCC/G++ or another compiler that supports C++11 or later.

Verify the installation:

```bash
g++ --version
```

### Install FFmpeg

FFmpeg must be installed and accessible through the system `PATH`.

Verify the installation:

```bash
ffmpeg -version
```

The FFmpeg build must support MP3 decoding and the `libmp3lame` encoder.

## Compilation

Open a terminal in `compression-core/modules/audio/` and run:

```bash
g++ audioCompression.cpp -o audioCompression
g++ audioDecompression.cpp -o audioDecompression
```

On Windows, append `.exe` to the output names if needed.

## Usage

### Step 1: Compress an MP3 file

Place the input MP3 file in the project directory.

Run:

```powershell
.\audioCompression.exe sample.mp3 compressed_audio.huf
```

The program automatically converts the MP3 into temporary PCM data and compresses it.

### Step 2: Decompress the compressed file

Run:

```powershell
.\audioDecompression.exe compressed_audio.huf final_audio.mp3
```

The program reconstructs the PCM data and automatically generates the final MP3.

### Step 3: Verify PCM integrity

Compare the SHA-256 hashes of the original PCM and reconstructed PCM:

```powershell
Get-FileHash audio_temp_pcm.pcm -Algorithm SHA256
Get-FileHash audio_reconstructed_temp.pcm -Algorithm SHA256
```

Matching hashes indicate that the PCM files are identical.

## Compression Metrics

The program reports the original PCM size, compressed file size, compression ratio, and space saved.

**Compression ratio**

```text
Compression Ratio = Original PCM Size / Compressed File Size
```

**Space saved**

```text
Space Saved (%) =
    (1 - Compressed File Size / Original PCM Size) × 100
```

A ratio greater than 1 indicates compression. A ratio below 1 indicates that the compressed file is larger than the original PCM file.

The `.huf` file includes metadata, so the measured ratio accounts for both the Huffman bitstream and its header.

## Custom File Format

The compressed file uses the `HUF1` format.

| Component | Description |
|---|---|
| Magic header | Four bytes identifying the format: `HUF1` |
| Original size | Original PCM size stored as a 64-bit unsigned integer |
| Frequency table | 256 frequency values, each stored as a 64-bit unsigned integer |
| Encoded bitstream | Huffman-encoded PCM bytes packed into bytes |

The integer fields are stored in little-endian order. The decoder uses the original byte count to stop at the correct point and ignore padding bits in the final encoded byte.

## Important Notes

- Huffman compression and decompression are lossless for the PCM input.
- MP3 decoding has already discarded information during the original lossy encoding.
- Re-encoding the reconstructed PCM into MP3 may produce different audio data and file sizes.
- The current implementation uses a fixed PCM format: 44.1 kHz, stereo, signed 16-bit little-endian samples.
- The current implementation uses shell commands to invoke FFmpeg and is intended as an educational prototype.
- Compression efficiency depends on the input data and the overhead of the custom file format.
